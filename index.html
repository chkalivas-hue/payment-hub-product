Network & Message Profiles
A Message Profile tells the ISO 20022 Engine how a routed payment must be represented for a specific rail or scheme. It binds a route to the message family, ISO version and mapping/validation profile; the Routing Engine still decides which route is used.
Example
CBPR_PLUS_PACS008 may generate the CBPR+ version of pacs.008, while SEPA_SCT_PACS008 applies SEPA-specific mapping and validation although both belong to the pacs.008 family.

PROCESSING LAYER
Engines & responsibilities

  
Orchestration Engine
Coordinates the workflow and ensures mandatory AML / Anti-Fraud clearance before any Core posting request.
Validation Engine
Runs structural, business and configuration validations, calls AML and Anti-Fraud APIs, and controls the pre-posting decision gate.
Routing Engine
Selects rail, scheme, correspondent, Nostro and processing profile.
ISO 20022 Engine
Maps Canonical + Routing Decision into the required ISO message.
Network Adapter
Handles connectivity to the selected payment infrastructure.
Reconciliation Engine
Matches Hub, Core, network and settlement records.
